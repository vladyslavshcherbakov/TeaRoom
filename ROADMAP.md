# Roadmap

The next tasks, in order. Each ends with something that opens on an iPhone from GitHub Pages.

## The first story

1. The user reads every line of the archer's wife and the lines change to the agreed tone.
   - Does the third cup get a second move, where the keeper gives no advice and the guest decides alone? The user answers.
2. The rules of the game logic get integration tests, and the presenters get unit tests.
3. The game keeps the evening in the browser, so a reload continues it.
4. The later visits of the archer's story are written: the hare from the moon, the apprentice's return for the flask.

## Art and sound

1. Every guest is redrawn after the wife's three portraits: an asymmetric pose, an expression told by gaze, mouth and shoulders, and the lantern's light.
   - Are the wife's new portraits the right manner for the other guests? The user answers.
2. The room has less bare wall.
3. The window gets views for seasons and weather, and the room a seasonal branch.
4. The old room's painted bowls come back as pictures of bowls.
   - Their paintings were removed with the 3D room. Do they return as drawn bowls? The user answers.
5. The room gets sound: the kettle, the pour, the night outside.

## The teahouse

1. The first day teaches the game: Mei in the evening, the mistress of the spring at night.
2. Guests tell contradicting stories about the grandmother, and the keeper can play along.
3. The keeper's skills grow from how they talk and brew.
4. Gifts from guests work in a talk: a given bowl is a line the guest answers.
   - Which legends follow the archer's wife? The user answers.
   - How many legends and evenings does the game have? The user answers.
   - What is the game called? "The Teahouse on the Pass" is a working name. The user answers.
